The included source closure is derived from that pinned commit. Selected source headers have been
adapted to Lean 4.34's public module format to reduce import memory usage:
module, public import, and @[expose] public section. The recorded migration exposes 72 helpers, renames 7 colliding helper names,
and removes two redundant rfl steps after simp has already closed the goal.
Mathematical statements are unchanged. The full patch is retained in
lean/evidence/comparison-module-headers.patch, and every packaged source is
hash-pinned in lean/evidence/source-manifest.json. The packaged OAI/ directory
contains only the 797 imported modules, without a nested Git checkout.

and LogTwo.Geometry.SectionIdealBridge for Lean 4.35.0-rc4 and single-file scope:

The local lean4web/checkpoints/ edition partitions the reduced source blocks
into separate public Lean modules. It adds narrower per-checkpoint imports and
synchronous elaboration, retaining every original block verbatim. Each generated
file identifies these modifications in its header. Source correspondence and
hashes are recorded in lean4web/checkpoints/manifest.json. The final target uses
the same independent project definition; no mathematical statement is weakened.

The single-file lean4web/LogTwoLean4WebPaste.lean edition adds editor-metadata
controls to the reduced source: asynchronous elaboration and style linters are
disabled, and 7,784 by-proofs are wrapped in a tactic that omits internal editor
information while executing the original proof steps. Outer command information
is retained; the independent definition and final target are not wrapped.
Progress messages and four explicit Mathlib instance-provider imports are added
(for cohomology and tensor constructions). The header identifies these changes. Removing
the wrappers and insertions recorded in lean4web/paste-source-map.json restores
the reduced source exactly. All notices, kernel checking and errors remain.

LogTwo/Geometry/JetTruncation.lean adapts the proof of
OAI.PiExponent.FormalLogTruncation.formalLog_packets_surjective_iff_truncated.
The adaptation uses different Y-centers and scales the same global polynomial
at each center before applying the common formal-series shift.
Other geometry files use the upstream polynomial-frame and local-contact APIs.
LogTwo/Geometry/InterpolationBridge.lean adapts the packet-surjectivity argument
from Approximation/FormalMatrixSurjectivity.lean to the varying Y-centers and
the actual rational matrix, with rational determinant descent added.
LogTwo/Geometry/AuxiliaryAtCenters.lean adapts Jets/FormalAuxiliaryJet.lean to
varying Y-centers and adds the simultaneous derivative-word consequence.
LogTwo/Geometry/CurveWordVanishing.lean adapts
Cohomology/CurveDerivativeVanishing.logarithmic_words_vanish to arbitrary nonzero
Y-centers and a finite family of actual normalized contacts, without the
global rigidity import.
LogTwo/Geometry/ContactFamilyAt.lean adapts Geometry/CurveContactFamily.lean
to varying nonzero Y-centers and a total center choice for the complete finite
place set; it assembles the auxiliary polynomial and derivative vanishing.
These additions do not establish the irrationality exponent of log 2.

LogTwo/Geometry/SeparatedWeights.lean adapts the finite-index conversion in
Geometry/AdmissibleCurveWeights.lean; SeparationAssembly constructs denominator
thresholds using Approximation/WeightSeparation.lean.
LogTwo/Geometry/PersistentRigidity.lean adapts the logarithmic implication in
Geometry/CurveFieldRigidity.lean and the cutoff argument in
Jets/NormalBasisProducts.lean. These component lemmas take a persistent normal comparison as input.
LogTwo/Geometry/NormalComparison.lean now adapts the logarithmic proof from
Approximation/PersistentWeightComparison.lean to discharge that input, using
Jets/TransverseSliceComparison.lean. IntrinsicContactBound.lean adapts the
nonconstant-coordinate argument from Geometry/CurveInequalityIntrinsic.lean
and uses Geometry/PlaceLocalRing.lean to derive the local field hypotheses.
The varying-Y centers replace the original fixed Y=1 centers.
These results do not establish the main theorem.

LogTwo/Geometry/JetIdealAt.lean adapts the radical, support, and packet-vanishing
arguments in Jets/CompactJetPolynomial.lean and Jets/CompactLogJetIdeal.lean
using the inverse Y-scaling equivalence. JetIdealContact.lean connects these
ideals to Analysis/LogarithmicContactIdeal.lean and the normalized branch lifts.
JetIdealCRT.lean applies Mathlib's Chinese Remainder Theorem to the resulting
coprime ideals; it makes no weighted-degree claim.

LogTwo/Geometry/CompactJetIdealAt.lean adapts Jets/CompactLogJetIdeal.lean
to arbitrary Y-centers, with an explicit affine-pullback identity and a unit-ideal
statement away from the centers. JetProductContact.lean combines local-ring
units, the computed radical, and the existing one-center colength identity.

LogTwo/Geometry/IntegralProj.lean extracts the graded-domain Proj lemmas from
Ampleness/BlowupProperIntegral.lean. WeightedCompactification.lean and the
support arguments in WeightedJetIdeal.lean adapt the compactification part of
Ampleness/AdmissibleBlowupGeometry.lean to the actual rational matrix weights
and varying Y-centers. The affine section-ring ideal calculation follows
Ampleness/ExceptionalCurveDegree.localIdeal_specIdeal. This adaptation does not
import the fixed-Y curve inequality or assert the main theorem.

LogTwo/Geometry/NormalizationBranch.lean uses the global extension and stalk
isomorphism results in Geometry/CurveGlobalMonomial.lean and
Geometry/CurvePlaceCenterStalk.lean. Its centered-map uniqueness argument
adapts Ampleness/ExceptionalCurveDegree.centerMorphism_eq_centeredLift to
varying nonzero Y centers and the constructed weighted compactification.
The global map is constructed rather than assumed.

LogTwo/Geometry/JetCenterAt.lean adapts Jets/JetCenterIdentification.lean
to varying Y-centers. CurveIdealSupport.lean adapts the generic-unit and
off-support local-ideal arguments in Ampleness/ExceptionalCurveDegree.lean.
Its radical argument and finite colength cycle reuse this project's earlier
varying-center ideal and contact-family results. No line-bundle degree
identity is asserted by these new modules.
